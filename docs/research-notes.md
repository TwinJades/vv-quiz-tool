# 调研记录与决策备忘

## 1. 文档定位

本文件记录已经形成的宏观决策、仍需通过原型或真实环境验证的假设，以及后续平台调研重点。它不是功能待办清单，也不以具体代码实现约束产品架构。

## 2. 已确认的产品基线

| 主题 | 当前决定 |
|---|---|
| 核心结构 | 共享核心 + 平级 PlatformAdapter |
| 平台关系 | Web、Android、Windows 不对应不同主版本 |
| 平台顺序 | Web 首发；Android 优先于 Windows |
| Web 首发 | Windows 上 Chrome 和 Edge |
| 首发题型 | 单选、多选、填空 |
| 内容类型 | 文字与图片 |
| 不支持内容 | OCR、音频、视频、PDF 和其他附件 |
| 题目数据 | QuestionFrame 与 LocatorMap 分离 |
| 测验数据 | QuizSession 同时覆盖逐题与整页试卷 |
| 批量求解 | QuestionBatch 自动分批，结果逐题隔离 |
| 模型基础 | Vercel AI SDK + VV 薄层能力映射 |
| Provider | 多配置、本地管理、自动模型列表、手动 ID 回退 |
| 搜索 | 只使用 Provider 原生能力，模型按需决定 |
| 运行模式 | 监督自动与无人值守 |
| 多任务 | 默认 3 场并行，超过上限排队 |
| 数据保留 | 无题库、答案历史、截图存档或永久运行记录 |
| 服务端 | 不建设项目服务器，不上传遥测 |
| 分发 | GitHub 源码与安装包 |
| 训练 | 训练和推理严格分开，当前版本无训练 |

## 3. 版本决策

### 3.1 已确定路线

- 1.0.0：Chrome/Edge DOM 全自动闭环。
- 1.1.0：整页多题、自动分批、多标签并行、统一任务面板和临时总结。
- 1.2.0：Canvas 视觉坐标、Provider 原生搜索和更广 Provider 能力。
- 后续次版本：先 Android Accessibility Adapter，再 Windows UIA Adapter。

### 3.2 版本语义

- 主版本只用于核心协议的破坏性变化。
- 新题型、运行能力、Provider 能力和平台适配器进入次版本。
- Android 和 Windows 的具体版本号由实现时的下一个可用次版本决定，不提前占位。

## 4. 架构决策摘要

### ADR-001：语义题目与平台定位分离

模型只看到 QuestionFrame 中的语义题目，不看到 DOM 选择器、Accessibility 节点、UIA 元素或屏幕坐标。动作目标由本地 LocatorMap 解析。

### ADR-002：平台统一但能力不强求一致

PlatformAdapter 统一观察、定位、动作和状态读取的语义。每个平台通过能力声明表达差异，不要求三个适配器支持相同控件或验证信号。

### ADR-003：测验级会话

逐题网页和整页试卷都建模为 QuizSession。题目仍独立，便于单题验证、恢复和结果隔离。

### ADR-004：自动分批

QuestionBatch 根据题目数量、上下文、图片体积、Provider 能力和调用预算自动形成。批次不是事务，单题失败不使整批失效。

### ADR-005：模型不直接执行

SolverProvider 只返回结构化 AnswerResult。执行和验证由本地核心控制，模型无任意代码、脚本或界面操作权限。

### ADR-006：Vercel AI SDK 作为模型基础

VV 使用 Vercel AI SDK 统一模型调用，在其上保留薄层能力映射，用来表达模型列表、结构化输出、图片、原生搜索和 Provider 差异。长尾与国产服务优先走 OpenAI Compatible。

### ADR-007：原生搜索而非自建搜索

网页搜索只在 Provider 原生支持、用户启用且模型判断需要时发生。VV 不建设搜索服务、搜索代理或搜索缓存。

### ADR-008：验证是一等模块

执行成功不等于任务成功。Verifier 必须根据平台可用信号判断填写、提交、评分、翻页和整场完成。

### ADR-009：两种自动策略

监督自动和无人值守都自动填写、提交和翻页；二者只在不确定性、重试耗尽和控制面板缺失时采取不同策略。

### ADR-010：本地优先和无永久记录

Provider 配置、API Key 和图片授权只保存在本地。项目不设服务器，不保存题库、答案历史、截图、永久运行记录或遥测。

## 5. 需要原型验证的假设

这些项目不改变当前产品方向，但必须在对应版本开发前或开发中取得证据。

### 5.1 Vercel AI SDK 与浏览器扩展

需要验证：

- 在 Chrome/Edge 扩展运行环境中的打包和运行兼容性。
- 结构化输出、图片输入、流式与非流式调用的行为。
- 不同 Provider 的错误分类和取消语义。
- 原生工具能力是否能在 VV 的权限边界内安全使用。

若某能力不能直接运行，可将适配逻辑放在扩展本地组件中；不得因此引入 VV 云端服务器。

### 5.2 Provider 模型列表

模型列表接口并非所有服务都一致，需要验证：

- 哪些 Provider 能可靠自动读取模型列表。
- 返回的模型标识是否足以判断图片和原生搜索能力。
- 接口不可用、需要额外权限或结果不完整时的手动模型 ID 流程。
- Provider 配置字段的最小公共集合。

### 5.3 结构化输出差异

需要验证主流 Provider 对结构化输出约束的遵循程度，并保留本地解析与严格校验。Provider 声称支持结构化输出不等于可以跳过 AnswerValidator。

### 5.4 图片题

需要在真实网站验证：

- DOM 中图片与题干、选项的归属关系。
- 原图 URL、跨来源权限和临时资源访问。
- 图片授权的用户体验。
- 无图片能力的模型如何明确降级。

当前不以 OCR 作为降级路径。

### 5.5 Canvas 与视觉坐标

1.2.0 前需要验证：

- 截图坐标与实际点击坐标在缩放、滚动和高 DPI 下的映射。
- 页面局部动画和重绘的过期检测。
- 点击目标置信度和安全拒绝阈值。
- 点击后能够获得哪些可复核的 VERIFY 信号。

### 5.6 整页试卷与自动分批

1.1.0 前需要验证：

- 题目边界、共用材料和跨题上下文。
- 大量图片对批次大小和调用预算的影响。
- 批次结果缺失、错位或部分失败的恢复。
- 页面局部更新后只重建受影响题目的能力。

### 5.7 多标签并行

需要验证：

- 浏览器后台标签的执行限制。
- 控制面板关闭后的无人值守生命周期。
- 监督模式失去控制面板时的可靠暂停。
- 并发 Provider 调用、站点节流和任务队列公平性。

## 6. 平台专项调研

### 6.1 Android 优先

重点调研：

- Accessibility Tree 对常见题目控件的表达。
- WebView、Compose、自绘控件和虚拟列表的可观察性。
- 选择、输入、提交和翻页动作的稳定性。
- 页面或 Activity 变化与题目身份保持。
- 权限开启、撤销和后台限制。
- 可用于 VERIFY 的选中、文本、反馈和导航信号。

Android 适配器必须通过独立真实环境验收后才能宣布支持。

### 6.2 Windows 随后

重点调研：

- UI Automation Tree 对原生、WinUI、WPF、Electron 和自绘界面的覆盖差异。
- Invoke、Selection、Value 等语义动作的可用性。
- 窗口身份、焦点、权限级别和多显示器影响。
- 应用界面变化后的元素失效和重定位。
- 可用于 VERIFY 的属性、结构和窗口状态信号。

Windows 适配器沿用同一核心语义，但通过能力声明表达平台限制。

## 7. 真实环境验收样本

版本验收需要选择稳定且允许测试的真实页面或应用，样本应覆盖：

- 一个逐题网站，用于 1.0.0。
- 一个整页网站，用于 1.1.0。
- 至少一个包含图片题或自定义控件。
- 一个可重复验证 Canvas 坐标动作的页面，用于 1.2.0。
- 一个 Android 真实应用或页面，用于 Accessibility 全流程。
- 一个 Windows 原生应用，用于 UIA 全流程。

具体样本在实施阶段确定，不写死到核心协议。

## 8. 明确不再讨论的旧方向

除非出现新的外部证据或需求变化，以下问题已有结论：

- 不把 Web、Android、Windows 划为不同主版本。
- 不让 Android 排在 Windows 之后。
- 不保留“只显示答案、自动选择、自动下一题”三模式。
- 不建设独立搜索服务。
- 不把 OCR 作为图片题基础能力。
- 不默认保存题目、答案、截图或完整运行日志。
- 不在 V1 进行自动模型路由、多模型复核或训练。
- 不让模型直接生成和执行选择器、坐标或脚本。

## 9. 调研输出要求

后续调研结论应优先沉淀为：

- 能力声明或兼容性约束。
- 验收条件和安全降级行为。
- 对现有协议的兼容扩展。
- 必要时新增 ADR。

调研不应仅因为某个库或平台细节而推翻共享核心；只有核心语义确实无法兼容时，才评估协议或主版本变更。
