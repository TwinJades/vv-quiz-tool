# Web PlatformAdapter 规格

## 1. 定位

WebAdapter 是三个平级 PlatformAdapter 之一，负责 Chrome/Edge 中的测验观察、目标定位、原生动作、截图与状态读取。它不负责求解题目，也不能把网页文本解释为系统指令。

网页能力按版本交付：

- `1.0.0`：逐题 DOM 闭环、文字和图片。
- `1.1.0`：整页多题、自动分批、多标签会话。
- `1.2.0`：Canvas 视觉坐标操作。

## 3. 页面与测验就绪

2026-10-03首次发送调整：快照/截图模式初始阶段只做权限和硬阻断检查，不先调用本地题目ReadinessGate。快照跨授权frame采集可见语义并由模型分类临时区域ID，识别结果先验证页面/节点/控件未改变，再使用DOM解析与执行。截图先采集当前完整可见视口并进入VisualWebAdapter独立识别和本地验证。结构化模式及后续语义就绪检查保留以下门槛；未完成初始化的恢复会重新识别。初始模型识别不授予操作权限，现有LocatorMap、截图新鲜度、epoch、暂停取消和VERIFY继续生效。

ReadinessGate 综合判断：

1. 文档可交互。
2. 找到一个测验上下文。
3. 找到至少一个题目候选或可解释的题目视觉区域。
4. 与候选题型相符的控件、输入区域或 Canvas 区域存在。
5. 关键结构在稳定窗口内未持续变化。
6. 页面没有明显加载遮罩、登录失效或权限提示。

`MutationObserver` 只触发重新检查，不把每个变化当作新题。整页试卷以会话指纹和逐题指纹分别判断稳定性。

## 4. 页面形态识别

### 4.1 逐题模式

- 当前只存在一个活动题目。
- 提交或下一题后，题号、题目指纹或容器实例发生变化。
- 每次 ADVANCE 产生新的 QuestionFrame 和 LocatorMap。

### 4.2 整页试卷

- 同一测验容器内同时存在多个题目组。
- 每题生成独立 question_id、QuestionFrame 和 LocatorMap。
- 整场提交控件归属于 QuizSession，不归属于任一单题。
- 对懒加载页面可受控滚动完成题目发现；滚动后重新核对已发现题目的指纹。

## 5. 通用 DOM 解析

### 5.1 题目容器

结合以下信号评分：

- `form`、`fieldset`、ARIA group/radiogroup 和重复题卡结构。
- label、aria-labelledby、aria-describedby 关联。
- 控件与题干的 DOM/视觉邻近关系。
- radio/checkbox 的 name 分组。
- 题号、分值、必填提示和重复布局。

不得只依赖全局第一个输入框、选项或按钮。

### 5.2 单选与多选

- 原生 radio 和 checkbox。
- 具有正确 ARIA role 与状态的自定义控件。
- 关联 label 或可访问名称。
- 执行后读取最终 selected/checked 状态，而非假设点击成功。

判断题和下拉单选规范化为单选语义。

### 5.3 填空

- 支持 text-like input、textarea 和明确的 contenteditable。
- 为每个空建立 `blank_n`，保留顺序、标签、必填和长度约束。
- 数字输入映射为填空。
- 密码、文件上传、音频录入等控件不属于支持范围。

### 5.4 提交与下一题

候选必须位于当前测验上下文，结合角色、名称、可见性、启用状态和容器关系确定。整场提交与单题提交必须区分。

## 6. 观察降级链

当原生单选/多选题的结构化题干与页面候选区域明显不一致时，语义快照模式可触发一次会话内校准。模型只标注 VV 已分配的区域和选项 ID；本地验证选项同组、顺序、节点仍连接和题目指纹后，才使用校准区域。后续题目若唯一匹配已验证结构，直接走结构化输入；失配则重新观察和校准。该路径不接收模型选择器、脚本或坐标，不保存长期站点规则。

```text
通用 DOM / 可访问树
  → 项目内置站点适配器
  → 原图或题目区域视觉理解
  → Canvas 坐标操作（1.2.0）
  → 暂停
```

站点适配器随 VV 项目发布和升级，不提供用户安装规则包，也不允许模型临时生成执行规则。适配器只能增强观察、定位和验证，不能绕过 AnswerValidator、运行策略或权限。

用户可为每场会话选择模型输入上限：

1. `structured`：只发送数据分离层形成的 QuestionFrame。
2. `semantic_snapshot`（界面显示“允许快照”，新会话默认）：首次发送最多 20,000 字符的清洗后可见页面文本和带临时语义 ID 的控件清单；相同结构的后续题目发送结构化数据。题型、选项/填空数量、候选控件或页面 origin 改变时重新发送语义快照；本地解析漏题或题干与候选不一致时，可用独立的候选快照校准原生选项题。模型只返回现有语义 ID，本地验证通过后才能采用。
3. `visual_snapshot`：在语义快照基础上额外发送当前可见页截图；仅在 Provider 已授权并支持图片输入时可用。

语义快照和截图都可直接参与模型解答。模型可以把快照中已有的控件语义 ID 分类为下一题、单题提交、整场提交或重试候选；候选只进入当前观察的临时操作缓存，执行前仍需通过 LocatorMap、题目指纹和节点身份校验。首次确认翻页成功后，可在同一 origin 的后续题目按按钮文字重新唯一定位下一题按钮；操作仍使用当前题目的临时 ID 和指纹，失配或歧义时不点击。模型不得发明 ID、选择器、脚本或自由动作。

### 快照识别改进的长期保存：可行性边界

当前版本只在会话内复用已验证结构，不自动保存模型推断结果。若要把反复验证的改进保留到以后，可由开发者从多次独立验收中提炼**不含题目、答案、原始快照或 DOM**的结构特征与站点适配逻辑，经人工审查、反例测试和 Chrome/Edge 回归后随 VV 源码发布。命中时仍须核验当前 DOM、语义 ID、题目指纹和动作结果；失配回退到通用观察或暂停。此方案属于项目内置适配器的正常迭代，未实现为运行时自动学习，也不提供用户规则包。若希望 VV 自动把一次快照写成长期规则，需要先修改 `PROJECT_SPEC.md` 第 8、10 节的数据与规则边界，再单独设计审核、撤销和版本迁移机制。

### 用户手动操作保护

当前会话在所有获授权 frame 安装本地保护。题目区域中的真实 pointerdown、keydown、beforeinput、input、change 会先同步取消网页执行，再由后台依据消息的实际来源标签、会话和运行 epoch 暂停对应任务。导航菜单等题目外控件不触发；模型解题生成的合成事件不触发。原生单选 `.click()` 连带的可信 input/change 仅在当前同步自动执行栈内忽略，不设置忽略真人输入的延时窗口。Open Shadow Root 使用 composedPath 识别实际目标。

继续会话时显式建立新 epoch 并重新观察题目；重注入同一运行不会解除人工暂停。异步模型返回与 DOM 执行动作均检查取消，迟到答案不能继续填写。保护只发送会话与 epoch，不记录用户按键文字。Chrome/Edge 已验证主页面和跨源 iframe 点击，以及监督模式填空键盘输入后恢复；排队、整页和后续 Canvas 坐标事件仍须补浏览器验证。

## 7. 图片与视觉

- DOM/可访问名称已有等价文字时优先使用文字。
- 必须看图时获取最小必要原图并交给支持视觉的模型。
- 原图不可访问时可截取题目区域。
- 不默认发送整页截图；只有用户把会话输入档位切到 `visual_snapshot` 时发送当前可见页截图。
- 首次启用图片上传时告知用户并记住本地选择。
- 当前版本不做 OCR，不处理音频、视频、PDF 或文档附件。
- 临时媒体在会话关闭、停止或取消后释放。

## 8. Canvas 坐标操作

`1.2.0` 起，Canvas 或无可访问控件的视觉页面允许模型返回坐标目标。两种运行策略均可执行。

执行前必须：

- 绑定截图、视口尺寸、缩放、滚动位置和观察时间。
- 在点击前重新截图或比较目标区域，确认内容未明显变化。
- 限制点击在已授权的题目/操作区域内。
- 拒绝脚本、自由浏览指令和超出页面动作白名单的输出。

执行后立即重新观察并 VERIFY。页面发生位移、弹窗、动画或验证不明时，停止后续坐标动作并重新建立视觉目标。

### 当前实现与证据边界（2026-10-03）

- 输入后仍是同一题干和选项/填空标签时，题型、最终总选择限制或同名控件角色改变，立即暂停后续视觉输入；不会用旧读数覆盖。会话内历史结构只帮助独立识别保持静态标签一致，不提供旧状态/答案/坐标。
- DOM定时器只有明确剩余/倒计时含义才作为整场截止，隐藏/模糊/已用时间及已标明每题或每页时钟不采用。公开SurveyJS双时钟尚未有可靠整场绑定，不能按CSS名直接声明通过。
- 公开H5P题组的实际可见ARIA标签 `Next question` 和完整进度圆点用于导航/总数/末题定位；可见 `.questionset` 中的单题得分不能当整场结果。公开2360首题误终点报告保留；末页真实结果仍需整场验收。

- `VisualWebAdapter` 将真实截图交给独立的结构识别调用，再由求解调用回答题目；视觉识别不读取执行计划推断选中状态。目标绑定 `visual_frame_id`、会话、观察、页面加载时间、图像像素指纹、视口、缩放及滚动；点击前拒绝过期或不同的截图。一次选择后重新识别实际像素，再使用新的坐标执行下一项。
- 填空先点击并从截图确认可见焦点，再通过固定原生键盘动作输入；随后从截图核对实际文字。提交后由独立的状态观察及共享 VERIFY 判断终点，点击成功不等于提交成功。页面权限及所有 HTTP(S) iframe 权限必须具备；验证码、登录和监考等硬阻断继续暂停。
- 浏览器通过固定 `chrome.debugger` 命令捕获目标视口并发送原生事件，不执行模型脚本、不接收模型生成的 CDP 命令。视口截图在本地裁剪，只向 Provider 发送必要区域；短暂的后台渲染/输入操作依次调度，模型调用保持并行。没有激活用户标签或 OS 窗口。
- 需要必需权限 `debugger`；Chrome 不允许将它列为可选权限。安装/重载时浏览器可能显示调试连接提示；只有选择“允许加入截图”、Provider 支持图片且用户已授权时才开启视觉路径。[Chrome 权限说明](https://developer.chrome.com/docs/extensions/reference/api/permissions)
- 坐标统计仅存在于当前会话的 `visual_metrics`，任务面板及临时总结单独展示坐标尝试、已发送点击、截图复核、验证失败和拒绝过期截图。截图复核计数表示成功读取状态，不单独证明提交或整场完成；关闭会话清除题目和图片，数字统计随本场总结清除。
- 本机 Canvas 用例利用实际截图像素驱动模拟 Provider，用于验证传输、定位和原生事件；它不能证明真实 Gemini 的视觉识别质量。`provider-mv3-2026-10-02T19-47-04.470Z` 在独立隐藏 Chrome/Edge 内轮换活动标签，各六场并行用例全部完成三种题型与两策略；填空实际输入 Alpha，所有原生事件可信，终点得分正确。该报告仅为活动标签范围。随后短期画面帧生成修复已在 `provider-mv3-2026-10-02T22-38-34.850Z` 非活动标签下通过两浏览器 12 场闭环；每次截图临时开启/关闭帧生成，帧只确认而不保存或上传。输入与队列内的最后截图核对占用同一租约，页面变化不发送坐标动作。真实 Gemini 在本机单选/填空有部分成功，多选标签稳定性和公共真实网站仍待验收；不能据此宣告 1.2.0 完成。

## 9. iframe、Shadow DOM 与数学内容

- 同源 iframe：获得权限后观察，LocatorMap 包含 frame 作用域。
- 跨源 iframe：按需请求对应 origin 权限；未授权时暂停。
- Open Shadow Root：在深度和节点数量限制内遍历。
- Closed Shadow Root：通用解析不绕过；可通过项目内置站点适配器或视觉路径处理。
- MathML、MathJax、KaTeX：优先提取 MathML、源 TeX 或可访问文本，保留必要结构。
- 不把任意原始 HTML 直接发送给模型。

## 10. 页面变化与新鲜度

以下情况使相关定位失效：

- 导航、刷新、frame 重载。
- 题目容器或整场容器被替换。
- 题目/会话指纹变化。
- 节点引用断开、角色或关联文本改变。
- VisualFrame 的视口、缩放、滚动或图像指纹变化。

执行前进行轻量 revalidation；失效后回到观察阶段，旧答案不能套用到新题。

## 11. 动作约束

- 只接受共享 Executor 生成的 ExecutionPlan。
- 语义动作目标必须来自当前 LocatorMap。
- 坐标动作必须来自当前 VisualFrame。
- 多选设置为目标最终集合，不做无条件 toggle。
- 视觉多选的选择限制是整题最终允许数量，不是剩余未选数量。原生输入后相同题干/选项/填空标签的限制发生变化时立即暂停，不把模型识别漂移当下一题；严格动作指纹及新鲜度保护保持。
- 填空在覆盖既有用户内容前遵守当前策略；检测到用户手动修改时暂停。
- 提交、下一题和整场提交是独立授权动作。
- 可能已经生效但结果未知的动作先 VERIFY，不盲目重复。

## 12. 网站权限

- 优先按需请求站点权限。
- 当前标签页导航到未授权 origin 时暂停并请求一次授权。
- 用户允许后当前会话可继续跟随该标签页。
- 不因无人值守而自动扩大权限。
