# 执行、验证与恢复

## 1. 目标

执行层负责把经过校验的 AnswerResult 转换为平台动作，并通过独立的 Verifier 判断动作是否真正生效。它不重新求解题目，也不能因为“已经点击”就假设答题成功。

本文件同时定义逐题网页、整页试卷、多标签并行、错误反馈重试和限时收尾的统一运行语义。

### 2026-10-03 公共Canvas反馈与终点

后台Canvas原生指针操作在同一输入队列租约内保持目标模拟焦点和帧生产，点击后最多等待4秒让标记/结束动画继续，再独立读取实际像素。模拟焦点只影响该网页目标，不激活OS窗口；临时流帧仅确认/丢弃，不存储或上传。等待可取消，嵌套截图不提前关闭外层流，取消/结束均释放。这个等待不能作为操作成功证据，旧帧/越界/不可靠读数仍拒绝。

自动评分后，题目控件可能已消失且成绩页出现。答题等待一旦读到平台completed立即交给Verifier，不再反复寻找旧控件或点击旧Submit；仍要求实际独立完成信号和动作验证。逐题已验证结果按指纹记账，失败前进后重观测同题不重复累加或重置故障恢复次数。公共网站的完成判定仍须报告和最终PNG复核，本机通过不能替代真实整场。

## 2. 会话状态机

每个 QuizSession 独立运行以下状态机：

    CREATED
      ↓
    WAIT_READY
      ↓
    OBSERVE_SESSION
      ↓
    VALIDATE_OBSERVATION
      ↓
    PARSE_SESSION
      ↓
    BUILD_BATCH
      ↓
    SOLVE
      ↓
    VALIDATE_ANSWER
      ↓
    ACT
      ↓
    VERIFY
      ├─ 成功且还有题目 → ADVANCE / OBSERVE_SESSION
      ├─ 答错且可重试 → REPLAN / SOLVE
      ├─ 页面变化 → OBSERVE_SESSION
      ├─ 可恢复故障 → RETRY
      ├─ 需要人工处理 → PAUSED
      └─ 测验完成 → COMPLETE

限时测验在剩余 60 秒时进入 CLOSE_OUT，停止启动低优先级工作，使用已经获得的最佳答案完成当前可执行动作，并在截止前提交。

### 2026-10-03 实际收尾路径

2026-10-03 08:26：截止与取消等待覆盖图片读取和模型请求，而不是只覆盖模型。DOM 剩余时间可在等待中出现或缩短；无已知计时器时，人工暂停仍可结束不响应取消的等待。截止前取消慢图片，迟到 payload 不进入求解或 ACT；整页只提交已验证答案、未答留空，逐题仍需明确整场提交控件。两浏览器×两策略实际挂起图片 HTTP 用例均零模型调用、一次提交并完成 VERIFY；不是所有慢视觉操作或公共限时网站已验收。

监督模式首次进入 CLOSE_OUT 发出一次“VV 正在收尾”通知请求；同一场重复状态、暂停/恢复不重复发出，无人值守收尾不发该请求。暂停/失败仍按新事件通知。通知交付失败不能打断自动执行。独立测试构建在构建时仅将通知发送点替换为记录器，各工作线程写入同一 session store，明确记录未发送 OS 弹窗；这证明请求策略，不证明用户桌面实际送达。

DOM/视觉状态返回已观察剩余时间，本地单调时钟在两次观察之间补算；停滞或缺失显示不能续期。模型请求等待时，每 500 ms 只读 DOM 定时器，可以缩短实际截止；Canvas 使用已识别计时和单调补算，不增加收费视觉轮询。倒计时进入最后 60 秒会停止新搜索及低优先级题目重试，优先原本未答题；剩余至少 5 秒留给提交，挂起求解会 abort，迟到结果不进入 ACT。

整页仅提交已经验证的答案，未获得有效答案的题目留空并计 skipped；逐题必须有明确整场提交控件。截止为零且网站还未完成时暂停，不再发送晚到动作。提交后仍检查实际整场终点，缺控件/提交未生效不标记 COMPLETE。人工暂停也中止等待与计时轮询，不会等到原模型请求自己返回。

隐藏 Chrome/Edge 中真实 DOM 的“显示停滞”和“模型等待期间截止缩短”四场本机用例均一次提交、正确保留未答题且迟到回复不改结果；这是功能证据，真实限时网站、两策略和慢视觉操作的收尾仍待验收，五秒预留不保证任意网站响应时间。

## 3. 两种运行模式

两种模式都自动填写、提交并进入下一题，区别只在不确定性处理策略。

| 场景 | 监督自动 | 无人值守 |
|---|---|---|
| 正常且高置信度 | 自动继续 | 自动继续 |
| 答案不确定 | 暂停并提示 | 采用当前最佳答案 |
| 页面结构不确定 | 暂停并提示 | 在安全降级仍能确认目标时继续，否则暂停 |
| VERIFY 信号不足 | 暂停并提示 | 可按策略重试；仍无法确认则暂停 |
| 答错且存在反馈 | 重新求解，必要时等待确认 | 自动重新求解 |
| 候选与重试耗尽 | 暂停 | 按会话策略停止、猜答或跳过 |
| 模型服务持续中断 | 暂停 | 暂停 |
| 验证码、登录失效、权限不足、明确技术阻断 | 暂停 | 暂停 |
| 控制面板关闭或不可用 | 暂停 | 后台继续 |

模式切换只改变策略，不改变题目协议、平台适配器或模型接口。

## 4. 逐题与整页测验

### 4.1 逐题网页

每次只观察当前题目，完成 SOLVE → ACT → VERIFY 后再触发下一题。翻页后必须重新观察，旧 LocatorMap 不得跨页复用。

### 4.2 整页试卷

一次观察形成一个 QuizSession，每题仍拥有独立的 QuestionFrame + LocatorMap。系统把待答题目加入 QuestionBatch，按题型、媒体大小、上下文长度、Provider 能力和调用预算自动分批。

批次结果必须逐题对应：

- 单题结果缺失、无效或失败，只影响该题。
- 有效答案可以继续执行，不因同批其他题失败而回滚。
- 失败题可以重新分批、单独求解或按运行模式暂停。
- 页面发生结构变化后，仅重新确认受影响题目的定位和状态。

## 5. 答案校验

执行前至少校验：

- 会话 ID、题目 ID 和观察版本匹配。
- 答案类型与 QuestionFrame.type 匹配。
- 选择题只引用题目中存在的语义选项 ID。
- 多选答案无重复项并满足站点已知约束。
- 填空答案数量与空位数量一致。
- 批次中的每个结果都能唯一对应一题。
- Provider 返回的说明文本不会被解释为动作指令。

无效结果不得直接传给 Executor。

## 6. 执行计划

Executor 根据平台能力和 LocatorMap 生成 ExecutionPlan。优先级由平台适配器决定，但必须遵守以下原则：

1. 优先使用稳定的语义定位和原生控件动作。
2. 站点适配规则只用于补充通用观察。
3. 视觉坐标操作仅在语义目标不可用且页面状态可确认时使用。
4. 提交、翻页和结束测验属于高影响动作，必须在动作前再次确认会话和页面状态。

Canvas 或其他视觉页面执行坐标点击前，必须确认截图版本、窗口尺寸、缩放、滚动位置和页面关键特征没有变化；点击后立即进入 VERIFY。

关键特征的像素保护覆盖独立视觉识别的全部题干/选项/填空矩形与可见控制的中心区域。截图保留完整摘要及16×16块的SHA-256摘要：有可靠区域和完整块摘要时，只允许保护区域之外的正计时或装饰变化；被保护的任意块变化仍拒绝，缺少摘要退回整图比较。几何、文档、会话及60秒时效检查始终保留，原生输入排队后再次截图核对，指针不能落在保护区域之外。识别区域无法可靠分离时不得擅自省略题目部分。

视觉输入后等待真实选中/焦点/文字最多3秒，以100毫秒间隔读本地画面，不重复发送点击。无状态变化时不能把发送输入当成功；取消释放等待定时器。非倒计时页面关键像素不变可复用识别结果，变化则重新识别。只有明确标记为倒计时的视觉读数才传给收尾计时，正计时或孤立0:00不触发收尾。

## 7. VERIFY 语义

Verifier 独立于 Executor，根据可用信号判断阶段结果：

- answer_applied：选项选中或文本已经写入。
- question_submitted：当前题已提交。
- graded：页面给出正确、错误或部分正确反馈。
- advanced：已进入下一题或题目状态已变化。
- session_submitted：整场测验已提交。
- session_completed：出现完成、成绩或结束状态。

验证结果不得只依赖单一信号。可组合使用：

- 控件状态或可访问属性变化。
- DOM、Accessibility Tree 或 UIA Tree 的结构变化。
- 当前题号、进度、按钮状态或反馈文本变化。
- 页面 URL、标题、路由或会话状态变化。
- 视觉区域变化，但不得仅以像素变化推断答案正确。

平台能力不足时，Verifier 返回“不确定”而不是伪造成功。

## 8. 答错后的恢复

页面给出错误反馈且允许继续尝试时：

1. 记录本次候选、反馈文本和已经排除的答案。
2. 将反馈作为受控事实加入新的求解上下文。
3. 重新求解；需要时尝试下一个有效候选。
4. 首次答案之后默认最多重试 2 次。
5. 每次重试后都重新执行答案校验和 VERIFY。

达到上限后：

- 监督自动模式暂停并展示原因。
- 无人值守模式按照本场策略停止、使用最佳剩余猜测或跳过。
- 若站点不允许重试，不得通过刷新或其他方式绕过限制。

## 9. 模型与网络故障

模型网络故障默认最多重试 3 次，并使用有限退避。重试期间不得重复执行页面动作。

仍然失败时，两种模式都暂停当前会话并提示用户。系统不得把 Provider 中断当作低置信度答案，也不得随机生成答案。

达到每场模型调用上限时视为明确技术阻断；默认上限为 300，用户可以在会话开始前调整。

## 10. 页面变化与人工操作

观察结果携带页面版本。若执行前发现版本不一致，丢弃旧定位并重新观察。

检测到用户手动点击、输入、导航或提交时：

- 当前自动动作安全停止。
- 重新读取页面和题目状态。
- 已经完成且可验证的结果予以保留。
- 无法判断冲突时按模式暂停，不与用户争夺控制权。

## 11. 多会话调度

不同标签页的测验是彼此隔离的 QuizSession：

- 默认最多同时运行 3 场，用户可以调整。
- 超过上限的会话进入队列。
- 每场拥有独立的 Provider、模型、调用预算、重试计数和状态。
- 一个会话失败不得阻断其他会话。
- 页面动作必须绑定到创建该会话的标签页，禁止跨标签执行。
- 无人值守模式在切换标签页或关闭控制面板后继续。
- 监督自动模式失去控制面板时暂停。

## 12. 暂停、恢复与通知

2026-10-03：模型求解、视觉识别和文字快照结构识别的重试等待均响应取消并在结束时移除监听；求解/结构请求在取消后不会启动下一次收费请求。结构识别通过同一会话预算计费，网络失败最多三次。暂停时TabPlatformProxy还会释放不响应取消的结构等待，迟到角色不能发送本地应用或写入会话结构；这不代表所有网站资源或慢视觉操作的计时验收已经完成。

暂停时保留内存中的会话上下文，但不写入永久运行记录。恢复前必须重新观察页面，不能直接继续使用暂停前的定位。

需要用户处理的异常通过浏览器通知和界面提示显示，包括：

- 登录失效或页面权限不足。
- 验证码、监考或访问控制阻断。
- Provider 不可用或调用额度耗尽。
- 页面结构无法可靠识别。
- 坐标目标无法确认。

## 13. 会话结束

结束后只生成临时 SessionSummary，包含题目数量、成功、失败、跳过、重试、调用次数、耗时和主要错误。关闭或清除会话后总结消失，不作为题库、答案历史或永久日志保存。

## 14. 验收场景

2026-10-03默认预算实查：`provider-mv3-2026-10-03T00-50-00.626Z/`独立隐藏Chrome/Edge，每浏览器两策略300次实际本机HTTP/300题ACT及VERIFY，停在第301题、未选择、未提交；继续仍300次，清除移除摘要。同场自定义3次连续503两策略均三次暂停且零答题、继续不超额。外部模型调用0，这是MV3额度及故障的实际执行证据，不是公共网站或真实模型质量证据。首份报告错误读取网页ISOLATED环境缺失计数而失败，原报告保留；通过报告明确读取MAIN环境的页面计数。

执行与验证至少覆盖：

- 单选、多选、填空的填写、提交、翻页与完成。
- 错误反馈驱动重新求解，且重试不超过默认上限。
- Provider 连续失败 3 次后暂停。
- 监督模式遇到不确定状态暂停。
- 无人值守模式在低置信度但无技术阻断时继续。
- 限时测验在剩余 60 秒进入收尾并提交当前最佳结果。
- 整页批次中单题失败不影响其他题。
- 三场并发和超额排队。
- 标签页切换、控制面板关闭和用户手动干预。
- Canvas 点击前页面变化检查及点击后 VERIFY。
