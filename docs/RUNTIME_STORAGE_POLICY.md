# 浏览器验收资料的保留与清理

## 为什么此前占用较大

2026-10-03 清理前，`.browser-regression-runtime` 共 10,259,907,435 字节（9.55 GiB），97,305 个文件。每场独立测试创建浏览器资料和私有扩展构建，浏览器又下载缓存与组件；结束后未及时回收可重建的资料，导致重复积累。浏览器组件目录 `ProvenanceData` 和 `component_crx_cache` 合计约 3.22 GiB。

## 保留范围

- 所有已知自有测试场次根部的原始报告、日志、截图，包括失败和中止记录。
- 正在使用的人工验收资料 `visible-retry-20260930`、已安装浏览器 `chrome-cft`。
- `manual-reports`、`manual-recorder-connection.json`、根部辅助脚本及配置、来源不明的独立资料目录。
- 用户扩展 `dist` 和项目源码、依赖。

## 正确做法

1. 开始批量测试前查看目录大小，复用一份浏览器程序，使用自己的隔离资料。
2. 报告、日志、截图放在每场目录根部；测试完成或中止后保存真实结果，确认自有浏览器退出。
3. 及时回收该场的 `profile`、`chrome`、`edge` 和 `extension` 子目录。只保留实际需要的证据；特殊复现环境用 `KEEP_RUNTIME.md` 标记用途和清理条件。
4. 用以下 PowerShell 命令先预览，再执行。工具会检查路径、进程及重解析点，保护活动资料，将可清理项送入回收站，逐项写入清理报告，并核对保留证据的 SHA256。

```powershell
& .\scripts\Clear-VV-TestRuntime.ps1
& .\scripts\Clear-VV-TestRuntime.ps1 -Apply
```

5. 检查清理报告的 `errors` 为空且 `verified` 为 `true`；将报告位置和目录大小写入断点。回收失败时保留原文件，禁止使用永久删除作为替代。

旧报告中的私有浏览器资料或扩展构建路径清理后可能不存在，原报告不改写。恢复测试时应从当前源码重新创建私有环境。原始报告和截图仍可用于核验历史结果。

移入回收站会减少项目目录大小，但文件仍占用磁盘空间，直到用户自行处理回收站；本工具不会清空回收站。
