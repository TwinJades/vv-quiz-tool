# 运行资料管理

## 保存位置

自有隔离浏览器资料、构建暂存和原始验收证据保存在 Git 忽略的 `.browser-regression-runtime`。每场测试使用独立目录，报告、日志和截图保存在该场根部。

项目文档只说明当前行为、检查要求及未完成事项。原始测试资料单独保留，已解决的事项不留在工作断点中。当前 `dist`、使用中的浏览器资料、Provider 凭据和人工验收资料继续保留。

## 保留范围

- 已知自有测试场次的原始报告、日志、截图，包括失败和中止结果。
- 使用中的浏览器程序、登录资料、插件和实际加载的扩展。
- `manual-reports`、人工记录器连接配置及相关使用中的资料。
- 项目源码、依赖、用户 `dist` 和来源不明的独立资料。

需要保留复现环境时，在该场放置 `KEEP_RUNTIME.md`，说明具体子目录、用途和清理条件。仅保留实际使用中的环境，不重复积累浏览器程序和已经结束的私有构建。

## 浏览器资料清理

批量测试前查看运行目录大小。超过约 1 GiB 时检查已经结束且可以回收的资料。共用一份已经安装的测试浏览器，测试使用自有隔离资料，不操作用户浏览器或人工记录器。

场次结束并保存证据、确认浏览器退出后，及时回收可重建的 `profile`、`chrome`、`edge` 和 `extension` 子目录。测试程序和构建需要短路径，浏览器资料的预计绝对路径长度控制在 240 字符以内。

使用现有工具先预览，再执行：

```powershell
& .\scripts\Clear-VV-TestRuntime.ps1
& .\scripts\Clear-VV-TestRuntime.ps1 -Apply
```

已确认退休的场次或具体旧构建可以通过 `-SelectionFile` 指定 JSON 清单，使用 `retired_runs` 和 `retired_paths` 字段。工具检查实际路径、运行进程和重解析点，保护活动资料，并核验保留证据的 SHA256。

清理报告中的错误必须处理，保留证据摘要需要一致。回收失败时保留原资料并报告失败，不使用永久删除替代。清理资料不代表功能验收通过。

## 文件移除规则

所有文件和目录删除都进入 Windows 回收站。操作前验证绝对路径属于指定工作目录，拒绝符号链接、目录联接及其他重解析路径，并检查正在使用目标的进程。工具不自动清空回收站。

移入回收站会减少项目目录中的文件；这些资料在回收站中仍可能占用磁盘空间。恢复测试时从当前源码重新建立环境，原始报告继续保留。

依赖使用 pnpm 配置的共享缓存，`node_modules` 保留。清理浏览器资料不修改用户 Provider 配置、凭据或正式扩展。
