# 版本路线与开发阶段

## 1. 版本原则

项目采用语义化版本：

- 主版本：仅在核心协议或关键兼容边界发生破坏性变化时升级。
- 次版本：新增题型、运行能力、Provider 能力或平台适配器。
- 修订版本：兼容性的修复、稳定性提升和文档更正。

Web、Android、Windows 是共享核心之上的三个平级 PlatformAdapter，不分别占用不同主版本。Android 适配器优先于 Windows 适配器，但两者都只在达到独立验收条件后进入下一个可用次版本，不提前锁定版本号。

## 2. 版本总览

| 版本 | 核心成果 | 主要验收 |
|---|---|---|
| 1.0.0 | Chrome/Edge 可靠 DOM 全自动闭环 | 本地测试体系 + 一个真实逐题网站 |
| 1.1.0 | 整页多题、自动分批、多标签并行、统一任务面板、临时总结 | 增加一个真实整页网站 |
| 1.2.0 | Canvas 视觉坐标、Provider 原生搜索、更广 Provider 能力 | 视觉动作和能力映射专项验收 |
| 后续次版本 | Android Accessibility Adapter | Android 独立端到端验收 |
| 再后续次版本 | Windows UIA Adapter | Windows 独立端到端验收 |

至少一个真实网站应包含图片题或自定义控件。

## 3. 1.0.0：可靠的网页闭环

### 3.1 目标

在 Windows 上的 Chrome 和 Edge 中，通过 DOM 完成可靠的逐题答题闭环。

### 3.2 范围

- 单选、多选、填空。
- 文字题和网页图片题。
- DOM 观察、页面就绪判定和 Observation 校验。
- QuestionFrame + LocatorMap 分离。
- Vercel AI SDK 统一模型基础和 VV 薄层能力映射。
- 多个本地 Provider 配置，模型列表自动读取和手动模型 ID 回退。
- 每场测验独立选择 Provider 和模型。
- 监督自动与无人值守两种模式。
- 结构化模型输出、Answer 校验、执行、VERIFY 和下一题闭环。
- 错误反馈重新求解，默认最多 2 次答案重试。
- 模型网络故障默认重试 3 次。
- 默认每场 300 次模型调用上限。
- 限时测验剩余 60 秒进入收尾。
- 临时会话状态和基本错误提示。

### 3.3 不包含

- 整页试卷的完整批量执行。
- 多标签并行任务面板。
- Canvas 坐标操作。
- Provider 原生网页搜索。
- Android、Windows 原生应用适配器。
- OCR、音频、视频、PDF 和其他附件。
- 题库、答案历史、永久日志、遥测和训练。

### 3.4 验收

- 本地测试覆盖核心协议、状态机、答案校验、重试和 VERIFY。
- 在一个真实逐题网站完成观察、求解、填写、提交、验证、翻页和结束。
- Chrome 与 Edge 均完成安装和核心流程验证。
- 图片题能在用户授权后发送原图给支持视觉的模型。
- Prompt Injection 内容不会变成执行指令。
- Provider 连续失败后会暂停，不错误提交。

## 4. 1.1.0：测验级编排与多任务

### 4.1 目标

从单题循环扩展为完整 QuizSession 编排，同时支持逐题网页和整页试卷。

### 4.2 范围

- 整页多题识别，每题保持独立 QuestionFrame + LocatorMap。
- QuestionBatch 自动分批和批次结果逐题对应。
- 单题失败不使整批失效。
- 多个标签页并行运行独立测验。
- 统一任务面板、队列、暂停、恢复和浏览器通知。
- 默认最多 3 场并行，用户可调整。
- 无人值守在切换标签页或关闭控制面板后继续。
- 监督自动失去控制面板时暂停。
- 限时测验收尾和整场提交。
- 会话结束后的临时运行总结。

### 4.3 验收

- 增加一个真实整页网站端到端验收。
- 至少一个真实网站包含图片题或自定义控件。
- 批次中无效或失败的单题可以独立恢复。
- 三场会话并行且第四场正确排队。
- 会话之间的页面、Provider、调用预算和错误状态彼此隔离。
- 标签页切换、关闭控制面板和用户手动干预符合两种模式策略。

## 5. 1.2.0：视觉页面与 Provider 能力扩展

### 5.1 目标

覆盖缺少可用语义控件的 Canvas 或视觉页面，并扩展模型服务能力。

### 5.2 范围

- 截图理解和坐标目标定位。
- 两种模式都可执行视觉坐标操作。
- 点击前确认页面未变化，点击后强制 VERIFY。
- Provider 原生网页搜索，由模型按需决定是否使用。
- 更广的 Vercel AI SDK Provider 能力映射。
- 长尾和国产服务继续优先通过 OpenAI Compatible 接入。
- Provider 能力声明、降级和界面提示完善。

### 5.3 验收

- 页面滚动、缩放、窗口变化或截图过期时拒绝旧坐标。
- 坐标点击只作用于当前会话和当前题目区域。
- 无法确认视觉目标时按模式安全暂停。
- 网页搜索只在用户启用且 Provider 支持时发生。
- VV 不出现独立搜索服务或搜索结果缓存。
- 不支持的 Provider 能力能够明确降级，不伪造可用状态。

## 6. Android 适配器：后续优先次版本

Android 是网页能力成熟后的第一优先平台适配器。版本号由当时下一个可用次版本决定。

### 6.1 复用

- QuizSession、QuestionFrame、AnswerResult 和 QuestionBatch。
- SolverProvider、运行模式、重试、限时收尾和会话总结。
- Answer 校验、错误分类和大部分 Verifier 语义。

### 6.2 新增

- Android Accessibility Tree 观察与状态读取。
- 选择、输入、提交和翻页动作。
- Android 平台能力声明和权限引导。
- Android 专用定位与验证信号。

### 6.3 独立验收

必须在真实 Android 环境中分别验证：

- Accessibility 观察。
- 单选与多选。
- 文本输入。
- 提交。
- 翻页或题目切换。
- VERIFY。
- 权限撤销、界面变化和明确阻断时的安全暂停。

Android 适配器不需要与 Web 支持完全相同的控件或验证信号，但必须实现相同的核心答题语义。

## 7. Windows 适配器：Android 之后的次版本

Windows UIA Adapter 在 Android 验收完成后进入后续可用次版本。

### 7.1 新增

- Windows UI Automation Tree 观察与状态读取。
- 选择、输入、提交和翻页动作。
- Windows 平台能力声明、窗口绑定和权限边界。
- Windows 专用定位与验证信号。

### 7.2 独立验收

使用真实 Windows 原生应用验证与 Android 相同的语义能力：观察、选择、输入、提交、翻页和 VERIFY。平台缺少某种信号时必须通过能力声明和安全降级表达。

## 8. 暂缓事项

以下内容不进入上述已规划版本，除非之后另行决策：

- OCR。
- 音频、视频、PDF 和其他附件。
- 自动发现测验任务。
- 公共站点规则市场或云端规则下发。
- VV 自建网页搜索服务。
- 自动模型路由和多模型复核。
- 跨会话永久缓存。
- 题库、答案历史和截图归档。
- 项目服务器、账号系统、云同步和遥测。
- 训练、微调和数据集生产。
- 绕过验证码、访问控制、监考或站点技术阻断。

## 9. 每个版本的完成定义

一个版本只有同时满足以下条件才算完成：

- 该版本范围内的协议和产品行为已经写入规格。
- 对应功能通过与风险相匹配的本地测试。
- 版本要求的真实环境验收完成。
- Chrome、Edge 或相应平台的安装和权限流程可用。
- 安全边界、数据保留和异常暂停行为符合规格。
- 术语、版本、状态机、平台关系和路线图在全部文档中一致。
- 全部文档相对链接有效。
- GitHub 发布的源码和安装包对应同一版本。

## 10. 变更控制

- 新增平台适配器默认是次版本，不改变主版本。
- 新增题型或 Provider 能力默认是次版本。
- 不改变外部语义的修复使用修订版本。
- 若修改导致已有 QuestionFrame、AnswerResult、PlatformAdapter 或会话协议无法兼容读取，才评估主版本升级。
- 未达到验收条件的功能标记为实验性，不得仅因代码存在就宣称版本支持。
